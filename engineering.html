01 · Current role, global pharma company

An operational knowledge graph for engineers and AI agents

Problem

What an operations engineer needs to know is spread across observability, ITSM, CMDB, on-call and documentation tools. Agents have the same problem, and an answer nobody can trace is not useful during an incident.

Architecture

Decisions

  • Store no data. Every query resolves live from the systems of record, so there is no second copy to keep fresh or to secure.
  • Treat agents as first-class clients. The graph is exposed through an MCP server as well as a web UI. Most queries now arrive through agents.
  • Make every answer auditable. Access is role-based and audited per user.
  • Gate autonomy with evaluation. Datasets built from human-verified incidents (gold, silver, bronze) and weekly LLM-as-judge runs back the autonomy levels that define what an agent may do unsupervised. The incident agent moved from L1 (suggest) to L2 (act under guardrails) under that system.

Result

90%through AI agents
88%answered with data
0.6 sp50 latency
02 · My own product, public repo

Bookreader: an AI reading agent that lives in the browser

Problem

A reader that can answer questions about your books normally needs your books on someone's server. I wanted the agent to work with the library staying on the device, and to add server pieces only where a feature could not exist without them.

Architecture

Decisions

  • Encrypt sharing end to end. A shared link is encrypted in the sender's browser with AES-GCM 256. The key travels in the URL fragment, which browsers never send, so the server holds bytes it cannot read (ADR-053).
  • Validate model plans in code. The per-chapter plan the agent proposes is checked deterministically, with a proportional fallback (ADR-049).
  • Deterministic checks first, then a judge from another model family. Whatever code can verify, code verifies. An LLM judge scores only what needs judgement, and it never comes from the family under test, to avoid self-preference bias (EVALS.md).
  • Keep the MCP server local and read-only. External agents can read your library through a stdio bridge on your machine. It is not a public API and changes nothing (MCP README).

03 · Previous role, global pharma company

Autodispatcher: assigning incidents with a neural network

Problem

Incidents took a mean of 45 minutes just to reach the right engineer, before anyone started working on them.

Architecture

Decisions

  • Start from the data. I analysed 18 months of historical ticket assignments before building the classifier.
  • Assign, do not just suggest. The app assigns the incident to the right engineer itself, because the delay was in the assignment step.
