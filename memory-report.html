1. Tipos de Memoria

1.1 Short-term / Conversacional

Definición: Memoria activa durante una sesión, equivalente al context window del LLM.

Mecanismos:

  • Context window nativo: Los modelos actuales (Claude 3.5 Sonnet: 200K tokens, GPT-4o: 128K, Qwen 2.5: 128K) proporcionan ventanas amplias pero costosas.
  • Compresión de contexto: Técnicas de summarization incremental (Rush et al., 2023; Chen et al., 2023) que condensan turnos anteriores en resúmenes concisos.
  • Sliding window: Descarta las interacciones más antiguas cuando se acerca el límite.
  • Recency bias: Los modelos tienden a recordar mejor el final del contexto (efecto de posición).

Implementaciones concretas:

  • Hermes: Compresión automática (compression.enabled: true, threshold: 0.50, target_ratio: 0.20) que reduce el contexto al 20% cuando se alcanza el 50% del límite.
  • Claude Code: Ventana nativa de Anthropic + summarization automática en sesiones largas.
  • Open Interpreter: Ventana nativa del modelo subyacente sin compresión propia.

Limitaciones: Memoria efímera por definición. Cada nueva sesión empieza desde cero a menos que se use persistencia externa.

1.2 Long-term / Persistente

Definición: Almacenamiento duradero fuera del context window, accesible por retrieval.

Paradigmas:

BackendFortalezasDebilidades
Vector DBs (Chroma, Weaviate, Qdrant, Milvus)Búsqueda semántica rápida, fácil de integrarPérdida de estructura relacional, requiere chunking
Graph DBs (Neo4j, NebulaGraph)Relaciones explícitas, queries estructuralesComplejidad de construcción automática, overhead
SQL (PostgreSQL con pgvector)ACID, maduro, híbrido vector+FTSMenos optimizado para embeddings nativos
File-based (Markdown, JSON, SQLite)Simple, portable, sin infraestructuraSin búsqueda semántica nativa, escalabilidad limitada

Ecosistema de embedding models:

  • OpenAI: text-embedding-3-small (1536 dims, $0.02/M tokens), text-embedding-3-large (3072 dims)
  • Sentence Transformers: all-MiniLM-L6-v2 (384 dims, local, gratis), all-mpnet-base-v2
  • BAAI: bge-m3 (multilingüe, 1024 dims, retrieval optimizado)
  • Cohere: embed-english-v3.0 (optimizado para RAG)

Chunking strategies:

  • Fixed-size: División por N tokens con overlap (simple pero pierde semántica)
  • Semantic chunking: Divide en límites semánticos usando embeddings o LLM (Reimers & Gurevych, 2019)
  • Agentic chunking: El propio agente decide cómo dividir la información (Zhang et al., 2024)
  • Parent-document retrieval: Embedding de chunks pequeños, retrieval de chunks padres completos (Gao et al., 2023)

1.3 Procedural

Definición: Memoria de "cómo hacer cosas" — skills, tool definitions, políticas, workflows.

  • Skills/Hooks: Documentos estructurados (SKILL.md) que se cargan en el system prompt según el contexto de la tarea.
  • Tool schemas: Definiciones JSON de herramientas disponibles (funciones, parámetros, descripciones).
  • Policies: Reglas de seguridad, aprobaciones, restricciones de comportamiento.

Implementaciones: Hermes (SKILL.md + Curator), Claude Code (CLAUDE.md/AGENTS.md), Aider (.aider* files), OpenDevin (SWE-agent style JSON).

1.4 Episódica

Definición: Registro de experiencias pasadas — qué pasó, qué funcionó, qué falló.

  • Session transcripts: Registros completos de interacciones.
  • Trajectories/rollouts: Secuencias state-action-observation-reward.
  • Lessons learned: Extractos condensados de experiencias.
  • Case memory: Casos específicos de errores y sus soluciones.

2. Arquitecturas de Retrieval

2.1 Vector Search

Documentos se embeden → se almacenan en índice vectorial → queries se comparan por similitud de coseno/Dot product. Recall@k: métrica estándar de retrieval.

Embedding models por dominio:

  • General: text-embedding-3-small, bge-m3
  • Code: CodeBERT, Salesforce/codebert-base, bge-code
  • Multilingüe: bge-m3, paraphrase-multilingual-MiniLM-L12-v2
  • RAG optimizado: E5-mistral, gte-large

Chunking strategies comparadas:

  1. Fixed-size (N=512, overlap=128): Simple, rápido, pero fragmenta semántica.
  2. Semantic (LLM-driven): Divide en límites de tema. Más preciso pero más costoso.
  3. Recursive (por párrafo/sección): Equilibrio entre estructura y simplicidad.
  4. Agentic: El agente chunkea según el contexto de la query (Zhang et al., 2024).

Hybrid search: Combina vector similarity + keyword matching (BM25). Implementaciones: Elasticsearch/OpenSearch, pgvector + pg_trgm, Qdrant/HNSW, Weaviate.

2.2 Graph-based Retrieval

Representar conocimiento como grafo (entidades + relaciones) y hacer traversal queries.

  • Knowledge Graphs estáticos: Construidos de datos estructurados (DBpedia, Wikidata).
  • KGs dinámicos (LLM-as-graph-builder): El LLM construye y actualiza el grafo en tiempo real.
  • GraphRAG (Microsoft, 2024): Construye grafo de documentos → community detection → summarization por comunidad → retrieval jerárquico. Paper
  • KAG (Knowledge-enhanced Augmented Generation): Combina KG con embeddings.

Herramientas: Neo4j + LangChain, Graphiti (Baseten, 2024), Mem0 + Graph.

2.3 Semantic Routing

Un router (LLM o modelo pequeño) decide qué memoria consultar según la query.

Query: "¿Cómo configuré el firewall?"
Router → "procedural" → Skills DB → "firewall-setup" skill

Query: "¿Qué error dio el deploy del martes?"
Router → "episódica" → Session search → logs del martes
  • Multi-query routing: El LLM genera múltiples queries paralelas.
  • Adaptive routing: El router aprende qué rutas funcionan mejor con el tiempo.
  • Implementaciones: LangGraph (state graph), LlamaIndex (router query engine).

2.4 Hierarchical / Chunking Inteligente

MemGPT (layered memory):

  • System prompt: Configuración permanente.
  • Personal memory: Datos del usuario.
  • Chat memory: Historial conversacional (sliding window).
  • Archival memory: Almacenamiento vectorial de largo plazo.
  • In-memory storage: Memoria conversacional activa.

Hierarchical Retrieval (Rush et al., 2023): Nivel 1: Resumen del documento → Nivel 2: Resumen de sección → Nivel 3: Chunk individual. Retrieval de arriba hacia abajo (coarse-to-fine).

2.5 Recency vs Relevance Weighting

  • Linear decay: Score = similarity × exp(-λ × age).
  • Recency boost: Añadir factor de recencia al score de similitud.
  • Two-pass retrieval: Primero relevancia, luego filtrar por recencia.
  • Adaptive weighting: El LLM ajusta dinámicamente el peso.

Implementaciones: MemGPT (archival storage con scoring), Mem0 (memory graph con weights), Hermes (session_search prioriza sesiones recientes).

Honcho (Nous Research): Sistema de memoria persistente para Hermes con dialectic modeling y memory fusion. hermes honcho setup

3.2 Dialectic Modeling

Mantener múltiples "versiones" de la memoria y hacer que "debatan" para llegar a la versión más precisa:

  • Memory fusion: Combinar memories contradictorias en una síntesis.
  • Dialectic reasoning: Thesis (memory actual) + Antithesis (nueva información) → Synthesis (memory actualizada).
  • Honcho: Memory fusion con scoring de confianza por fuente.

3.3 FTS5 / Full-Text Search vs Embeddings

FTS5 (SQLite): Exacto, rápido para keywords, bajo overhead. Ideal para errores específicos, IDs, nombres técnicos.

Embeddings: Entiende semántica, maneja sinonimia, busca por concepto. Costoso, requiere infraestructura.

Híbrido: SQLite + fts5 + vector extension, pgvector + pg_trgm. Hermes usa session_search que combina FTS5 + embeddings.

3.4 Memory Budgets y Compresión Automática

  • Token budget: Límite de tokens para el contexto total.
  • Memory count budget: Límite de memories almacenadas.
  • Storage budget: Límite de espacio en disco.

Implementaciones: Hermes (compresión automática al 20% del tamaño al alcanzar 50% del límite), MemGPT (limits por capa), LangMem (budgets por session).

4. Evaluation y Benchmarks

4.1 ¿Cómo se mide si la memoria funciona?

Métricas de retrieval:

  • Recall@k: Proporción de documentos relevantes en los top-k resultados.
  • Precision@k: Proporción de resultados relevantes en los top-k.
  • MRR (Mean Reciprocal Rank): Promedio del inverso del rank del primer resultado relevante.
  • Faithfulness: Qué tan fiel es la respuesta generada a la memoria recuperada.
  • Answer relevance: Qué tan relevante es la respuesta para la query original.

Métricas de agent memory:

  • Memory utilization: Proporción de memories que el agente usa efectivamente.
  • Memory accuracy: Qué tan precisas son las memories almacenadas.
  • Memory retention: Cuánto tiempo retiene información útil.
  • Memory interference: Cuánto la nueva memoria afecta negativamente a la vieja.

Benchmarks adaptados de RAG: RAGAS (faithfulness, answer relevance, context precision), HELM (holistic evaluation), MT-Bench (multi-turno).

4.3 Pitfalls Comunes

1. Stale Memory (Memoria desactualizada)

La memoria antigua ya no es precisa pero sigue siendo usada. Mitigación: Decay weighting, periodic review, versioning.

2. Memory Explosion (Explosión de memoria)

La cantidad de memories crece exponencialmente, ralentizando el retrieval. Mitigación: Memory budgets, pruning automático, consolidation.

3. Context Pollution (Contaminación del contexto)

Información irrelevante se incluye en el contexto, distrayendo al LLM. Mitigación: Router de retrieval, filtering por relevancia.

4. Memory Hallucination

El agente "recuerda" cosas que nunca ocurrieron. Mitigación: Verificación de fuentes, confidence scoring.

5. Fragmentation

La misma información se almacena múltiples veces. Mitigación: Deduplication, memory fusion, canonical storage.

5.2 Análisis Detallado

Hermes Agent

  • Fortalezas: Sistema de skills robusto con curator automático, compresión de contexto automática, multi-plataforma (10+ gateways), auto-mejorable, plugin system extensible.
  • Debilidades: Retrieval básico (sin router automático), memory management manual.
  • Setup: curl -fsSL install.sh | bash — muy bajo.
  • Repo: NousResearch/hermes-agent (~150k stars)

MemGPT (Claude)

  • Fortalezas: Arquitectura de memory layers madura, auto memory management, paper académico sólido.
  • Debilidades: Requiere setup propio, dependencia de infraestructura externa.
  • Paper: arxiv.org/abs/2307.08653

Aider

  • Fortalezas: Git como memoria implícita (historial de cambios), simple, efectivo para coding.
  • Debilidades: Sin memoria semántica, sin retrieval.
  • Repo: paul-gauthier/aider

OpenDevin

  • Fortalezas: File system como memoria persistente, sandbox seguro, multi-agent.
  • Debilidades: Sin memoria semántica, retrieval básico.
  • Repo: All-Hands-AI/OpenDevin

LangGraph + LangMem

  • Fortalezas: Máxima flexibilidad (programable), LangMem soporta múltiples backends.
  • Debilidades: Requiere programar todo el flujo de memory, curva de aprendizaje alta.
  • Docs: langchain-ai.github.io/langgraph

CrewAI

  • Fortalezas: Multi-agent con roles definidos, simple de usar.
  • Debilidades: Memoria muy limitada, sin retrieval avanzado.
  • Repo: crewAIInc/crewAI

AutoGen (Microsoft)

  • Fortalezas: Multi-agent conversacional, integración con herramientas de Microsoft.
  • Debilidades: Memoria básica (solo chat history), sin retrieval.
  • Repo: microsoft/autogen

5.3 Recomendación para SRE con Agente Auto-Mejorable en Producción

Escenario: Un SRE que quiere un agente que recuerde incidentes pasados, aprenda de cada deploy, se auto-mejore con el tiempo y funcione en producción con baja latencia y alta fiabilidad.

Recomendación: Hermes Agent + Honcho Memory + PostgreSQL/pgvector

Por qué:

  1. Auto-mejorable: El sistema de skills crea automáticamente nuevas skills tras tareas complejas. El Curator las mantiene actualizadas.
  2. Memoria persistente: Honcho o Mem0 proporcionan memory fusion y dialectic modeling.
  3. Retrieval híbrido: session_search combina FTS5 + embeddings. Se puede añadir pgvector para búsqueda semántica avanzada.
  4. Producción: Multi-platform gateway (Telegram, Discord, Slack), cron jobs para monitoreo, webhook triggers.
  5. Baja complejidad: Setup con un comando, config en YAML.
